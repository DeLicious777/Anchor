# Assumptions Log

Running log of assumptions made across Vision, Concept, feature docs, and ADRs — surfaced explicitly rather than left implicit in conversation. Add an entry whenever a decision depends on something unverified.

**Cite assumptions by ID (`A1`, `A2`, …), never by row position or date.** IDs were added 2026-07-28 after the register grew four same-day rows and every positional citation in the doc set became ambiguous — the same reasoning that gave risks their `R` IDs. IDs are permanent and never reused, including for invalidated rows.

| ID | Date | Assumption | Status | Notes / Evidence |
|---|---|---|---|---|
| A1 | 2026-07-23 | Fully manual tracking (no passive/idle detection) will still deliver "no work forgotten" in practice, since nothing enforces that the user remembers to start/switch/interrupt tracking. | open | Explicitly scoped this way for MVP (determinism, privacy, user control) per `docs/vision/vision.md`; revisit after real personal usage. Tracked as risk **R3**. Note the 2026-07-28 Concept revision mitigates the *consequence* (timeline reconstruction lets forgotten work be added later) but not the *cause* — this assumption is unchanged by it. |
| A2 | 2026-07-23 | Auto-completing all skipped intermediate interruptions when the user chooses "Return to Original Task" matches real user intent every time. | open | Initially flagged as plausibly contradicting Vision's "never silently dropped" criterion (reviewer pass, 2026-07-23). Resolved at the design level by keeping skipped work distinguishable from finished work — originally via `completion_reason`, now via `InterruptionOutcome::Skipped` surfaced through `DerivedInterruptionStatus` ([ADR 0005](decisions/0005-event-model-time-block-metadata-and-reconstruction-transitions.md)). Whether it matches real user intent in practice remains open; tracked as risk **R1**. |
| A3 | 2026-07-23 | Export-time aggregation by exact match on task name/project/client (rather than a first-class Task entity with identity) is sufficient for useful billing reports. | open | Broadened per reviewer pass (2026-07-23): the risk isn't just typos, but any rename over time silently fragmenting historical totals, with no reconciliation path. Task Templates partially mitigate by giving a canonical source for names. Tracked as risk **R2**. Revisit once export/reporting is exercised on real data. |
| A4 | 2026-07-23 | A desktop-first app with global hotkeys is sufficient for "effortless" capture, even for interruptions that happen away from the desk (phone calls, in-person conversations), until a mobile client exists. | open | Mobile/CLI/browser clients are explicitly deferred; only testable once real usage away from the desk is observed. |
| A5 | 2026-07-23 | Existing time-tracking tools (Toggl, Harvest, Clockify, RescueTime) do not adequately solve the interruption-stack/return-to-original-task problem — i.e. this is a genuine gap, not a reinvention. | **invalidated** | **Narrowed, then invalidated, both on 2026-07-28** — the project's first competitive research, and its first invalidation from evidence rather than a design change. *First pass* found timeline editing definitively precedented (Toggl's Calendar view: click-drag to create, edge-drag to adjust, drag to move) and the stack mechanic precedented outside time tracking (`task-stack`), narrowing the claim to "the *combination* is unserved." *Second pass* invalidated even that: **ManicTime** (Windows, local-first, timeline-primary with manual editing, project/client tagging, Excel export, invoices from timesheets) and **Memtime** (local-only, automatic day timeline, built for transferring a captured day into an external project-time system — the Produra workflow, from a German vendor) both ship the combination; **org-mode** clocking serves it for a subset of the same persona. Two specific claims proved false: Toggl's Continue button *does* resume an interrupted task, and framing RescueTime as the passive alternative was a strawman (it is productivity analytics, not a billing tool). **Consequence:** `docs/concept/concept.md` was reframed from market differentiation to build-vs-buy; **A9** replaces this row. |
| A6 | 2026-07-23 | The author's prior Rust experience is sufficient that the Rust surface area chosen in ADR 0002 (hotkeys, tray, window management, log I/O/compaction, heartbeat timer, OS-level sleep/hibernate detection via raw Windows APIs) is a manageable ramp-up cost, not a project-stalling one. | open | Not stated either way during architecture discussion; treated as an open assumption rather than guessed at. Tracked as risk **R6**. Revisit once real implementation work on the Rust core begins. |
| A7 | 2026-07-23 | Billable-vs-non-billable classification does not need to be an explicit field in Anchor's data model — project/client attribution alone is sufficient, because the exported timeline feeds a separate, already-used billing process that performs the classification. | resolved-by-decision | A scope question only the author could answer, settled directly rather than through research. See [ADR 0003](decisions/0003-billable-classification-out-of-scope.md). Resolved a real gap: Vision's "Success looks like" previously implied Anchor itself splits billable/non-billable time, but no such field was ever defined on Time Block. Vision, MVP and Users amended the same day. |
| A8 | 2026-07-23 | JSON export should stay a raw, per-Time-Block record list (independently rounded per record) rather than grouped by task the way XLSX is. | invalidated | Flagged as unconfirmed rather than treated as decided. Reviewer pass (2026-07-23) found it would make XLSX and JSON diverge numerically (~3×) for identical data, in exactly the fragmented-interruption scenario the feature exists for. Corrected: JSON uses the same sum-then-round logic as XLSX when rounding is on, staying raw only when rounding is off. See `docs/product/features/export.md`. |
| A9 | 2026-07-28 | No evaluated tool provides an interruption model combining arbitrary stack depth, explicit root-task recovery, and persistent skip provenance. | open | The deliberately narrow replacement for **A5**. Stated as an assumption, not a conclusion: the search was not exhaustive and nothing has been evaluated hands-on. It is a claim about a *mechanic*, not a market position — per `docs/principles.md` #2, Anchor's reason to exist is deterministic manual capture ([ADR 0001](decisions/0001-manual-assisted-tracking-for-mvp.md)) against the automatic capture ManicTime and Memtime chose. That is a philosophy difference, not a feature gap, and it does not need this row to be true. |
| A10 | 2026-07-28 | The snapshot written by ADR 0004's compaction persists unresolved interruption stack frames, not merely closed Time Blocks. | resolved-by-decision | Was `open` for one day. **Load-bearing**: the sole reason `InterruptionOutcome` has no persisted `Pending` value. Supported by design intent (`log/reader.rs`'s replay takes `starting_stack: Option<InterruptionStack>` — the whole structure) but never stated in ADR 0004, which specifies compaction's mechanism and not its payload. [ADR 0005](decisions/0005-event-model-time-block-metadata-and-reconstruction-transitions.md) converts it into a specified guarantee, so it is no longer an assumption. If that guarantee is ever weakened, `Pending` must become a persisted value. Compaction remains unimplemented. Related: **R11**. |
| A11 | 2026-07-28 | An always-available reconstruction workspace will not erode in-the-moment capture discipline — i.e. knowing the timeline can be fixed later won't cause the user to stop capturing as it happens. | open | Introduced by the Concept revision making the Timeline editable. Directly in tension with the product being capture-first: if capture decays, reconstruction becomes the default path and Anchor re-creates the after-the-fact guesswork it exists to eliminate. Compounds **A1**/**R3** rather than replacing them. Now falsifiable rather than merely arguable — `docs/vision/vision.md`'s Capture Rate (≥90% provisional) is the test. Tracked as risk **R10**. |
| A13 | 2026-07-29 | Replay-stable Time Block identity scoped to **one log lineage** is sufficient; global uniqueness across unrelated Anchor histories is not required. | open | The load-bearing assumption behind [ADR 0006](decisions/0006-stable-persistent-time-block-identity.md)'s explicit non-goal. Grounded in accepted material rather than convenience: `docs/product/features/export.md` never specifies an `id` field (the value reaches full-fidelity JSON only because `TimeBlock` derives `Serialize`), the XLSX billing path carries Name/Project/Client/Duration and never an id, multi-user and sync are explicitly out of scope (`docs/product/mvp.md`, `docs/product/users.md`), no accepted ADR states an identity requirement, and import is named as *future* work in `docs/architecture/constraints.md`. **Testable, and it fails the moment any consumer depends on an exported id** — at which point ADR 0006 must be revisited, since a fresh log, a restored backup or a second install reuses ids for unrelated work. |
| A14 | 2026-07-29 | The snapshot written by compaction will persist each Time Block's `id` (or the `seq` it derives from), not merely the stack frames A10 already covers. | resolved-by-decision | Specified by [ADR 0006](decisions/0006-stable-persistent-time-block-identity.md). Recorded alongside **A10** deliberately: A10 exists because ADR 0004 specified compaction's *mechanism* and never its *payload*, and a decision was built on the unstated assumption. This is the same gap for a different field, and keeping both rows here means a future snapshot implementer finds the whole payload contract in one place rather than split between an ADR's prose and this log. Compaction remains unimplemented (#8). |
| A12 | 2026-07-28 | Anchor's flat model (name + optional project/client) maps onto Produra's project → sub-project → activity hierarchy well enough that transferring hours is a copy, not a rework. | open | A scope call (export format consideration only — no model change, no integration, `docs/product/mvp.md`), not verified against a real Produra instance or booking session. `export.md` fixes the XLSX columns at name/project/client/duration: four columns against a three-level hierarchy plus a client. If the mapping is lossy, either the export structure or the flat model gives. Tracked as risk **R12**. |

- **open** — not yet checked
- **validated** — confirmed by research, user feedback, or real usage; safe to build on
- **invalidated** — turned out false; note what changed as a result (which docs/ADRs needed revisiting)
- **resolved-by-decision** — not evidence-based; settled by an explicit author or architecture decision (cite the ADR). Distinct from `validated`: nothing was empirically confirmed, a scope call was made. Only revisit if the decision itself is revisited (new ADR), not through further research.

**Keeping this current:** never delete a row, even invalidated ones — the history of what we assumed and learned is more valuable than a tidy table. When an assumption is superseded, keep the old row, mark it, and point at the ID that replaces it (see **A5** → **A9**). Cite rows by ID from the doc or ADR that depends on them, never by position or date.
